# Cross-entropy = NLL = compression
STATEMENT: Training with cross-entropy is exactly maximum-likelihood estimation, and the loss is the expected code length (in nats/bits) of the data under the model: L = H(p_data) + KL(p_data || p_model). Minimizing CE is minimizing KL to the data distribution, i.e. building the best compressor; perplexity = exp(CE per token).
DERIVATION: Write MLE: argmax_theta E_{x~p}[log q_theta(x)] = argmin E[-log q] = CE(p,q). Decompose CE(p,q) = H(p) + KL(p||q); H(p) is the irreducible entropy floor, KL is the model's excess bits (Shannon: optimal code length for x is -log p(x)). Hence loss has an intrinsic floor, loss deltas are 'bits saved', and perplexity = exp(nats/token) = effective branching factor.
NUMBERS: Perplexity = e^loss (nats) or 2^loss (bits); good LLMs ~0.5-0.7 bits/byte on web text; ln(2)=0.693 converts nats to bits; entropy of English ~1 bit/character (Shannon).

# The 6ND rule and Chinchilla allocation
STATEMENT: Training compute C ≈ 6·N·D FLOPs (N params, D tokens); for fixed C, loss is minimized by scaling N and D together, roughly D ≈ 20N (Chinchilla), so N_opt ∝ C^0.5. Inference-heavy deployments deliberately over-train small models past Chinchilla-optimal.
DERIVATION: Each parameter does ~1 multiply-add = 2 FLOPs per token forward; backward costs ~2x forward (grads w.r.t. weights and activations), so 6 FLOPs/param/token → C=6ND. Fit L(N,D) = E + A/N^a + B/D^b (Chinchilla parametric form); minimize subject to 6ND=C via Lagrange → N,D both ∝ C^0.5 with the empirical fit giving D/N ≈ 20. Add the caveat: total cost = train + inference·(queries), so serving-dominated economics push to smaller-N, larger-D (Llama 3: D/N > 200).
NUMBERS: C≈6ND; Chinchilla ratio D≈20N; backward≈2x forward; A100 = 312 TFLOPS BF16, H100 ≈ 990 TFLOPS (sparse)/~500 dense; good MFU 40-50%; Chinchilla: 70B@1.4T beat Gopher 280B at same compute; Llama 3 8B trained on 15T tokens (~1900:1).

# Arithmetic intensity and the roofline
STATEMENT: Every kernel is either compute-bound or memory-bandwidth-bound depending on arithmetic intensity (FLOPs per byte moved) vs the hardware's ops:byte ratio. LLM decode at small batch is memory-bound (reads all weights per token); prefill and training are compute-bound. This single lens explains almost every inference optimization.
DERIVATION: Time = max(FLOPs/peak_compute, bytes/bandwidth). Hardware ridge point = peak_FLOPS/bandwidth (A100: 312e12/2e12 ≈ 156 ops/byte; H100 SXM ≈ 990e12/3.35e12 ≈ ~300). Decode batch-1 on 70B FP16: read 140GB weights, do ~140 GFLOPs → intensity ≈ 1 FLOP/byte → bandwidth time 70ms vs compute 0.4ms: 99% memory-stalled. Therefore: quantization (fewer bytes), batching (amortize weight reads), GQA/PagedAttention (shrink KV traffic), FlashAttention (avoid materializing n×n to HBM) all attack bytes, not FLOPs.
NUMBERS: A100: 2 TB/s HBM, 312 TFLOPS BF16, ridge ~156 FLOPs/byte; H100: 3.35 TB/s, ridge ~300; decode intensity ~1-10 FLOPs/byte, prefill 100+; 70B FP16 = 140 GB → ~70ms/token bandwidth floor on A100; decode becomes compute-bound around batch ~150 (worked in book).

# Attention is a differentiable soft KV lookup
STATEMENT: Attention(Q,K,V) = softmax(QK^T/√d)V is a soft dictionary lookup: queries score keys by dot product, and the output is the value average weighted by those scores. It gives content-based, permutation-equivariant, O(1)-path-length routing at O(n²d) cost, with √d scaling to keep logit variance ~1.
DERIVATION: Hard lookup: return V[argmax match(q,k)]; relax argmax to softmax → differentiable. Scaling: if q,k have i.i.d. unit-variance entries, q·k has variance d, so divide by √d to stop softmax saturation (vanishing gradients). Complexity: QK^T is n²d; FFN is ~8nd² (4x expand) — attention dominates FLOPs only when n > d. Multi-head = h parallel lookups in d/h-dim subspaces (same total FLOPs, richer routing). Permutation equivariance → need positional encoding. Causal mask → autoregressive; enables KV caching.
NUMBERS: Attention FLOPs O(n²d), FFN O(nd²) with 4x expansion (~8nd² per layer); params per layer ≈ 12d²; multi-head: h heads of dim d/h; typical d_head=64-128; transformer params ≈ 12·L·d².

# The training memory ledger
STATEMENT: Mixed-precision Adam training costs ~16-18 bytes per parameter before activations: FP16/BF16 params (2) + grads (2-4) + FP32 master weights (4) + Adam m and v (8). Activations scale with batch·seq·hidden·layers and are traded against compute via checkpointing; ZeRO/FSDP shard the per-param states across data-parallel ranks.
DERIVATION: List the tensors: weights, gradients, optimizer moments, master copy, activations. Adam keeps two FP32 moments = 8 bytes/param; mixed precision adds an FP32 master copy = 4; BF16 param+grad = 4. Total ≈ 16-18 → 7B model ≈ 112-126 GB, which is why 7B doesn't fit on one 80GB GPU without ZeRO/LoRA. Activations ≈ s·b·h·L·(constant ~10-30 bytes per element) — dominate at long context; gradient checkpointing recomputes them for ~30% extra FLOPs. ZeRO-1/2/3 shard optimizer/grads/params → per-GPU memory divided by DP degree. Contrast inference: just 2 bytes/param (or 0.5 at INT4) + KV cache.

# KV cache arithmetic
STATEMENT: Autoregressive decoding caches keys/values so each new token costs O(n) attention instead of O(n²) recompute; the cache costs 2·layers·kv_heads·d_head·seq_len·bytes per sequence and is the binding constraint on serving batch size and context length — motivating GQA/MQA, PagedAttention, and quantized KV.
DERIVATION: Under causal masking, past tokens' K,V never change → compute once, store. Memory: 2 (K and V) × n_layers × n_kv_heads × d_head × seq × bytes/elt. Worked: Llama-2-70B with GQA (8 KV heads, 80 layers, d_head 128, FP16): 2·80·8·128·2 ≈ 0.33 MB/token → 4K context ≈ 1.3 GB per sequence; batch 100 ≈ 130 GB — exceeds weights. Hence GQA (8x fewer KV heads ≈ 8x less cache), PagedAttention (eliminate fragmentation/over-reservation, ~2-4x more concurrent sequences), KV quantization, sliding windows.
NUMBERS: KV bytes = 2·L·n_kv·d_head·seq·bytes; Llama-2-70B GQA ≈ 0.3 MB/token, ~0.6 GB per 2K-context request; MHA would be 8x that; vLLM claims ~2-4x throughput from paging; book's worked example: 128 concurrent requests ≈ 77 GB KV + 35 GB INT4 weights on one 8xH100 node.

# Softmax–cross-entropy gradient is p − y
STATEMENT: The gradient of CE loss w.r.t. logits is simply softmax(z) − y: predicted probability minus target. Error signals are bounded, linear in miscalibration, and never saturate through the combined softmax+CE — which is why this pairing (and sigmoid+BCE) is numerically and dynamically the default.
DERIVATION: L = −log softmax(z)_y = −z_y + logsumexp(z). dL/dz_i = softmax(z)_i − 1[i=y] = p_i − y_i. Note softmax alone has Jacobian diag(p) − pp^T (can vanish when saturated), but composing with CE cancels it. Same structure for sigmoid+BCE (σ(z)−y) and for MSE on linear outputs — 'canonical link' pattern from GLMs. Implementation corollary: always fuse (logsumexp trick, subtract max) — never softmax-then-log. Temperature: dividing logits by T scales gradients and entropy; distillation multiplies KD loss by T².
NUMBERS: grad = p − y (bounded in [−1,1] per coordinate); softmax Jacobian diag(p) − pp^T; logsumexp: subtract max(z) before exp; distillation: scale soft loss by T².

# SGD noise is a feature: flat minima and the batch-size/LR coupling
STATEMENT: Minibatch gradient noise (variance ∝ lr/batch) is an implicit regularizer that biases SGD toward flat minima, which generalize better; consequently learning rate and batch size must be scaled together (linear scaling rule + warmup), and noise reduction hits diminishing returns past a critical batch size.
DERIVATION: SGD update = true gradient + zero-mean noise with covariance ∝ η/B · Σ. Treat as SDE: temperature ∝ η/B — doubling batch halves noise, so double η to keep the same dynamics (linear scaling rule); warmup needed because early large steps at high curvature diverge. Flatness: sharp minima are brittle under train/test distribution shift of the loss surface and noise kicks the iterate out of narrow basins; flat basins also have lower description length (MDL argument). Critical batch size ≈ gradient noise scale: beyond it, extra batch buys no wall-clock progress per FLOP.
NUMBERS: Noise temperature ∝ lr/batch_size; linear scaling rule breaks around B > ~8K for ImageNet-scale vision; warmup typically 1-3% of steps (LLMs ~2000 steps); accumulation of k steps × batch B ≈ batch kB in expectation.

# Adam is diagonal preconditioning; AdamW decouples the prior
STATEMENT: Adam rescales each coordinate's step by an EMA estimate of gradient magnitude (m/√v), approximating curvature-aware (preconditioned) descent — essential for transformers where gradient scales vary wildly across layers/tokens. AdamW applies weight decay directly to weights rather than through the adaptive scaling, restoring its meaning as an isotropic Gaussian prior.
DERIVATION: Newton's step is H⁻¹g; too expensive, so approximate H's diagonal by gradient second moments: v ≈ E[g²] → step η·m/(√v+ε) equalizes effective step sizes across coordinates (scale-invariant to per-coordinate gradient rescaling). Why transformers need it: rare tokens/embedding rows and LayerNorm interactions create orders-of-magnitude gradient-scale disparities that a single η can't serve. AdamW: L2-in-the-loss gets divided by √v (large-gradient weights barely decayed) — decoupling makes decay uniform, and empirically restores SGD-like regularization; also explains why 'weight decay' ≠ 'L2 regularization' exactly when adaptive.
NUMBERS: Defaults β1=0.9, β2=0.95-0.999, ε=1e-8; weight decay ~0.1 for LLMs; Adam states = 8 bytes/param FP32; typical LLM peak LR ~1e-4 to 3e-4 with cosine decay to ~10%.

# Residual stream + normalization = trainable depth
STATEMENT: Deep networks train because residual connections give gradients an identity path (grad = 1 + f') so signal can't vanish multiplicatively, and normalization (BN/LN/RMSNorm) keeps activations/gradients in a fixed scale regime. Pre-norm placement keeps the residual path clean, which is why modern LLMs are pre-norm + RMSNorm and train stably without warmup-critical tricks.
DERIVATION: Chain rule through L plain layers multiplies L Jacobians → norms compound exponentially (vanishing/exploding). With x_{l+1} = x_l + f(x_l), dL/dx_l = dL/dx_{l+1}(I + f') — the identity term guarantees a direct gradient highway; the network learns perturbations to an information-preserving stream (the 'residual stream' interp view). Normalization fixes the scale of inputs to each block, decoupling layers' learning dynamics and enabling higher LR. Post-norm puts LN on the residual path (stronger reps, needs warmup, unstable deep); pre-norm leaves the highway untouched (stable, the modern default). LN vs BN: LN normalizes per-token across features — batch-size independent, works for variable-length sequences and inference-time batch 1; RMSNorm drops mean-centering for speed.
NUMBERS: Residual gradient = 1 + f'; RMSNorm saves ~10-15% normalization wall-clock vs LN (book's figure); BN unreliable below batch ~8-16; He init variance 2/fan_in.

# Overparameterization generalizes: double descent and implicit bias
STATEMENT: Past the interpolation threshold (params ≫ needed to fit train data), test error descends again: among the many zero-train-loss solutions, SGD's implicit bias selects low-norm/flat/simple ones, so bigger models generalize better, not worse. Classical bias-variance intuition describes only the underparameterized regime.
DERIVATION: Draw test error vs capacity: classical U-curve, spike at interpolation threshold (model contorts to fit noise exactly), second descent beyond. Intuition via linear regression: with p>n, gradient descent from zero init converges to the minimum-l2-norm interpolant, which gets smoother as p grows. Neural nets: SGD noise + architecture bias play the same role; larger nets have more good basins, so found solutions are simpler functions despite more parameters. Corollaries: zero train loss is not overfitting per se; regularize by data/noise/early-stopping rather than capacity; grokking = delayed transition from memorizing to generalizing circuit under weight decay.
NUMBERS: Interpolation threshold at params ≈ n_train·classes (order of magnitude); modern LLMs are below 1 epoch (each token seen once) — a regime where train loss ≈ test loss and classical overfitting barely applies.

# Power-law loss curves; smooth loss, jumpy capabilities
STATEMENT: Test loss falls as a power law in N, D, and C over many orders of magnitude — smooth, predictable, and the basis for extrapolating training runs. But downstream task metrics need not follow: thresholded/exact-match metrics can jump ('emergence') even while the underlying loss improves smoothly.
DERIVATION: State L(x) = L_inf + a·x^(−alpha) → straight line on log-log after subtracting the entropy floor; fit small runs, extrapolate big ones (how frontier labs de-risk runs). Why power laws (if pushed): data has a long-tailed feature/skill frequency distribution; each new decade of scale mops up the next tranche of rarer features — sum of exponentials over a Zipfian spectrum yields a power law. Emergence: per-token loss improving smoothly can cross the threshold where a k-token answer is all-correct with high probability (p^k is sharp in p) — so 'emergent abilities' are substantially a metric artifact (continuous metrics smooth them out).
NUMBERS: Kaplan exponents roughly alpha_N≈0.076, alpha_D≈0.095, alpha_C≈0.05 (order of magnitude: loss drops ~2x per ~3-4 orders of compute); power laws hold over 7+ orders of magnitude of compute; k-token exact match ≈ p^k explains sharp benchmark jumps.

# Goodhart's law: optimizing a proxy breaks it
STATEMENT: When a measure becomes the optimization target, it stops measuring what you cared about. Every learned or hand-picked objective in ML is a proxy — reward models, offline metrics, benchmarks, engagement — and sufficient optimization pressure will find and exploit the proxy's gap from the true goal.
DERIVATION: True objective U is unmeasurable; you optimize proxy R = U + gap. Optimization seeks max R, and the max of R systematically lands where gap is largest (winner's-curse/extremal argument: conditioning on high R selects for high gap). Instances: RLHF reward hacking (policy exploits RM blind spots — sycophancy, verbosity, format tricks); benchmark contamination and benchmark-chasing; recsys engagement optimization → clickbait; offline NDCG up, revenue down. Mitigations share one shape: bound optimization pressure (KL constraints, early stopping against the proxy), keep held-out un-optimized measures (fresh human evals, holdout benchmarks), and iterate the proxy.
NUMBERS: No canonical constants; the quotable line: 'When a measure becomes a target, it ceases to be a good measure.' Rule of practice: any single metric optimized hard for long enough will be gamed — always pair a target metric with untargeted guardrail metrics and periodic human eval.

# KL-anchored preference optimization (what the KL buys)
STATEMENT: RLHF maximizes a learned reward minus beta·KL(policy || reference SFT model). The KL term is not a nicety: it bounds optimization pressure against an imperfect reward model (anti-Goodhart), keeps outputs on the language manifold the RM was trained on (keeping the RM in-distribution), and prevents catastrophic drift/mode collapse. DPO solves the same KL-regularized objective in closed form on preference pairs, replacing the RM+PPO machinery with a classification loss.
DERIVATION: Objective: max_pi E[r(x,y)] − beta·KL(pi||pi_ref). Without KL: policy climbs the RM into off-distribution regions where RM error is largest → degenerate high-reward gibberish (Goodhart). The KL-regularized optimum has closed form pi*(y|x) ∝ pi_ref(y|x)·exp(r/beta); invert: r = beta·log(pi/pi_ref) + const. Substitute into the Bradley-Terry preference likelihood P(y_w ≻ y_l) = sigma(r_w − r_l) → DPO loss: −log sigma(beta·[log pi/pi_ref(y_w) − log pi/pi_ref(y_l)]) — the policy becomes its own implicit reward model. Beta trades reward gain vs drift; too-low beta → hacking/collapse, too-high → no improvement (alignment tax framing).

# Prefill vs decode: two workloads in one request
STATEMENT: LLM inference has a compute-bound parallel phase (prefill: whole prompt at once, like training) and a memory-bound serial phase (decode: one token at a time, re-reading weights + KV). TTFT is governed by prefill, tokens/sec by decode; every serving technique targets one phase, and continuous batching + speculative decoding are the two highest-leverage decode fixes.
DERIVATION: Prefill: n tokens in one forward = big matmuls, intensity 100+ FLOPs/byte → compute-bound, TTFT ≈ 2·N·n_prompt/peak_FLOPS. Decode: batch-1 matvecs, intensity ~1 → bandwidth-bound, per-token floor ≈ model_bytes/bandwidth. Continuous batching: admit/evict requests per token step (not per batch) → no head-of-line blocking from long generations, 2-10x throughput. Speculative decoding: cheap draft proposes k tokens, target model verifies all k in ONE forward pass (parallel like prefill); rejection sampling keeps the target distribution exactly — spends idle FLOPs to cut serial memory-bound steps; helps at low batch, fades when acceptance is low or system is already compute-bound. Disaggregated serving: separate prefill and decode fleets.
NUMBERS: Decode floor ≈ weights_GB / bandwidth_GBps per token (70B FP16 on A100: 140/2000 = 70ms); prefill intensity ~100+ FLOPs/byte vs decode 1-10; speculative decoding typical 2-3x at batch~1 with ~70%+ acceptance; continuous batching 2-10x throughput vs static.

# Contrastive learning: InfoNCE, temperature, and collapse
STATEMENT: Contrastive objectives (InfoNCE) learn representations by pulling positives together and pushing apart in-batch negatives on a hypersphere; temperature sharpens the effective weighting toward hard negatives, and the central failure mode of all self-supervised embedding learning is collapse (all inputs map to one point), which negatives, stop-gradients (BYOL/SimSiam), or statistical regularizers prevent.
DERIVATION: InfoNCE = cross-entropy of identifying the positive among N candidates: −log[exp(s_pos/τ)/Σ exp(s_i/τ)] — i.e. softmax classification over the batch, lower-bounds mutual information (log N bound → wants large batches). Gradient weight on each negative ∝ exp(s_i/τ): low τ focuses on hardest negatives (too low → optimizes noise/false negatives). Without negatives the loss has a trivial global optimum: constant output (collapse); BYOL/SimSiam block it with predictor+stop-gradient asymmetry, VICReg with variance terms. Same math powers CLIP (symmetric InfoNCE over image-text pairs, learned τ) and two-tower retrieval (in-batch negatives = sampled softmax).
NUMBERS: InfoNCE MI bound ≤ log(batch_size); SimCLR batch 4096, τ≈0.1; CLIP learned τ (init 0.07), 400M pairs, batch 32K; embeddings L2-normalized so score = cosine.

# Bi-encoder decomposability and two-stage retrieval
STATEMENT: A two-tower/bi-encoder scores query-item pairs as a dot product of independently computed embeddings — precompute the corpus, index with ANN, retrieve in O(log N)-ish time; a cross-encoder attends across the pair for far higher accuracy at O(N) cost. Every retrieval/recsys/RAG system is the same pattern: cheap decomposable retrieval over millions, expensive joint reranking over the top-k.
DERIVATION: score(q,d) = f(q)·g(d) → all g(d) precomputable offline; retrieval = MIPS/ANN over stored vectors (HNSW/IVF). # Where fine-tuning lives: low-rank adaptation and the PEFT ladder
STATEMENT: Task adaptation of a pretrained model is intrinsically low-dimensional: weight updates ΔW during fine-tuning have low effective rank, so LoRA parametrizes ΔW = BA (rank r ≪ d) and trains ~0.1-1% of parameters at near-full quality — eliminating optimizer-state memory for the base model and making per-task serving cheap (adapters merge or hot-swap).
DERIVATION: Pretraining already learned general features; a downstream task mostly re-weights/redirects them → ΔW concentrated in a low-rank subspace (measure: spectrum of ΔW from full FT decays fast). Memory win compounds: no grads or Adam moments for frozen base (which were 12+ bytes/param) → QLoRA: base in 4-bit NF4 + LoRA in BF16 trains 65B on a single 48GB GPU. # Train-serve skew and the two-worlds problem
STATEMENT: Training and serving are different distributions, different code paths, and different objectives; models fail in production not because they're wrong but because the world they see at serving time differs from training — feature-computation mismatches, feedback loops (the model shapes its own future training data), temporal leakage, and drift.

# Quantization and the numerics ladder (FP32→BF16→FP8→INT4)
STATEMENT: Floating-point format = sign + exponent (range) + mantissa (precision). Training tolerates low precision but not low range — hence BF16 (FP32's 8 exponent bits, 7 mantissa bits) is the training default, while inference tolerates aggressive weight quantization (INT8/INT4) because you only need the forward pass's outputs to be approximately right, and decode is bandwidth-bound so fewer bytes = proportionally faster.
DERIVATION: FP16 (5 exp bits, max 65504) overflows on gradients → needs loss scaling; BF16 keeps FP32 range so overflow is a non-issue, and its 7-bit mantissa error is dominated by SGD gradient noise anyway — that's the key argument. Master weights stay FP32 because tiny updates (lr·grad ~1e-7 relative) would round to zero in 16-bit accumulation. Inference: weight-only PTQ (GPTQ/AWQ groupwise, scale+zero-point per 128 weights) halves-to-quarters the bytes read, directly cutting the decode bandwidth floor; activations/outliers are the hard part (per-channel scales, SmoothQuant). Quality cliff typically below 4 bits; QAT or NF4 for aggressive regimes.
NUMBERS: FP32: 8 exp/23 mant; FP16: 5/10, max 65504; BF16: 8/7, range ~3.4e38; INT8/INT4 = 1/0.5 bytes per weight; GPTQ group-128 overhead ≈ 6.25%; 70B: FP16 140GB → INT4 ~37GB; quality typically intact at 8-bit, small loss at 4-bit, cliff below.

# Parallelism triad: data, tensor, pipeline (+ ZeRO and MoE)
STATEMENT: Three orthogonal ways to split training across GPUs: data parallelism replicates the model and all-reduces gradients (bounded by memory per GPU); tensor parallelism splits individual matmuls (bandwidth-hungry — keep inside a node/NVLink); pipeline parallelism splits layers into stages (cheap comms, but pipeline bubbles). Real systems compose all three (3D parallelism) with ZeRO sharding the redundant states; MoE adds expert parallelism for sparse capacity.
DERIVATION: DP: each rank holds full model; sync cost = one all-reduce of gradient size per step; scales until model+states exceed one GPU → ZeRO-1/2/3 shard optimizer/grads/params to recover DP's simplicity at larger scale. TP: split each weight matrix column/row-wise; needs an all-reduce of activations per layer (~2·hidden·bytes) → fine on NVLink (~sub-ms), painful cross-node → TP degree ≤ 8 (one node). PP: assign contiguous layers to stages; only activations cross stage boundaries, but naive scheduling idles GPUs — bubble fraction ≈ (stages−1)/(microbatches+stages−1) → many microbatches. Compose: TP=8 within nodes, PP across nodes, DP+ZeRO across replicas (book has the 70B-on-256-GPU worked layout). Serving uses TP for latency, replication for throughput.
NUMBERS: TP all-reduce ≈ 2·hidden·bytes per layer (~32KB at h=8192, b=1); NVLink ~900 GB/s vs InfiniBand ~50 GB/s per node; bubble ≈ (p−1)/(m+p−1); ZeRO-1 saves ~4x memory (book table); typical recipe: TP=8, PP to fit, DP for the rest.

# Position is a modeling choice: RoPE, relativity, and context extension
STATEMENT: Attention is permutation-equivariant, so position must be injected explicitly. RoPE rotates Q/K by position-dependent angles so attention scores depend only on relative offset — which composes with the dot-product lookup, decays gracefully, and (crucially) makes trained context length extensible by rescaling rotation frequencies (position interpolation/NTK/YaRN) with little or no fine-tuning.
DERIVATION: Sinusoidal/learned absolute embeddings are added to inputs; relative schemes bias attention by (i−j). RoPE: pair up dimensions, rotate q_m and k_n by angles m·θ_i, n·θ_i with θ_i = base^(−2i/d) (base 10000): then q_m·k_n depends only on (m−n) — relative encoding via absolute rotations, applied inside the attention lookup. Extension: positions beyond training length produce out-of-distribution rotation phases; rescale (interpolate positions by factor s, or raise the base — NTK-aware) so seen-phase range covers the new length; high-frequency dims (local order) preserved, low-frequency (long-range) interpolated → YaRN. ALiBi alternative: linear distance penalty, extrapolates natively but caps long-range expressivity.
NUMBERS: RoPE θ_i = 10000^(−2i/d); position interpolation scale s = L_new/L_train; NTK/YaRN raise base (e.g. 10000 → 500000 in Llama 3.1 for 128K); ALiBi slopes geometric per head.

# Generative modeling = learn a transport from noise to data (ELBO and diffusion)
STATEMENT: All deep generative models learn a map between a simple distribution and the data distribution, trading off sampling speed, sample quality, and likelihood tractability (the trilemma). VAEs maximize the ELBO = reconstruction − KL (a lower bound on log-likelihood via Jensen); diffusion models denoise gradually — training a network to predict the noise at every corruption level, which is a reweighted ELBO and equivalent to learning the score ∇log p(x) — buying stable training and SOTA quality at the cost of many sampling steps.
DERIVATION: log p(x) = log ∫ p(x|z)p(z)dz ≥ E_q[log p(x|z)] − KL(q(z|x)||p(z)) (Jensen; gap = KL(q||posterior)). Reparameterization z = μ+σ⊙ε makes the bound differentiable. Diffusion: forward q(x_t|x_0) = N(√ᾱ_t x_0, (1−ᾱ_t)I) adds noise on a schedule; train ε_θ(x_t,t) with simple MSE ||ε − ε_θ||² (each step a tiny well-posed regression → no adversarial instability, no collapse); reverse by iterating denoising. Classifier-free guidance: sample with (1+w)·cond − w·uncond score to trade diversity for fidelity. Latent diffusion runs this in a VAE's latent space to cut compute ~48x. GANs: implicit likelihood-free transport — fast sampling, unstable minimax, mode collapse. Autoregressive: exact likelihood via chain rule (this is the LLM objective).
NUMBERS: ELBO = E[log p(x|z)] − KL(q||p); diffusion forward: x_t = √ᾱ_t x_0 + √(1−ᾱ_t)·ε; typical T=1000 train steps, 20-50 DDIM sampling steps; CFG scale ~5-9; latent diffusion ~8x spatial downsampling (~48x compute reduction).

# Tokenization is learned compression at the boundary
STATEMENT: Subword tokenization (BPE/Unigram) is a compression scheme fitted to the training corpus: frequent strings become single tokens. It sets the model's atomic units — so context length, cost, and a family of notorious failures (arithmetic, spelling, rare languages, code whitespace) are tokenizer artifacts, not model-intelligence artifacts.
DERIVATION: BPE: start from bytes, greedily merge the most frequent adjacent pair, repeat to vocab size — literally a compression algorithm (fewer tokens per text = better compression on corpus-like data). Consequences: (1) fertility varies — English ~1.3 tokens/word, low-resource languages 2-4x more tokens → less effective context and higher cost per content; (2) numbers split inconsistently ('2023' one token, '2024' maybe two) → arithmetic weirdness; (3) characters invisible inside merged tokens → spelling/counting failures; (4) vocab size trade: larger vocab = shorter sequences but bigger embedding/softmax matrices and rarer-token undertraining. Embedding matrix = vocab × d is pure lookup (the first 'attention-free attention').
NUMBERS: English ≈ 1.3 tokens/word (≈4 chars/token); vocab sizes: GPT-2 50K, Llama-2 32K, Llama-3 128K, Gemma ~256K; embedding params = vocab·d (128K·8192 ≈ 1B params); low-resource languages up to 3-4x token fertility.
