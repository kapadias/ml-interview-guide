# 1. PROGRAM ARCHITECTURE: Four-volume set + thin program spine (do NOT merge)
**Recommendation: multi-volume set with a shared spine — four content volumes plus a thin program-layer repo.** Do not merge into one mega-book.

**Why not one book:** (a) A merged volume would be ~50k+ LaTeX lines and 800+ pages before the P2/P3 additions, Vol III, and Conventional ML land — unbuildable in one sitting mentally and slow to compile; (b) the two repos have independent git histories, and the DL volume has an in-flight approved upgrade plan — a merge would invalidate every file path in that plan; (c) the volumes serve different rounds (a search-depth candidate should not carry the vision/GNN chapters); (d) the preambles are already ~99% identical, so the merge buys almost no dedup that a shared style file doesn't buy more cheaply.

**Concrete repo layout:**
- `deep-learning-essentials` (Vol I, exists) — foundations, architectures, training/optimization, systems; gains the P2 chapters (ML Coding Rounds, Agents, Pretraining-at-Scale, GPU Fundamentals, Staff Loop).
- `natural-language-processing-essentials` (Vol II, exists) — classical NLP through LLMs/alignment; keeps its unique canonical strengths (test-time compute, tool use, benchmark landscape, pretraining data lore).
- `search-recommendation-essentials` (Vol III, NEW) — see section 3. Absorbs DL ch12 and the ANN-systems half of DL ch7; new home for the Bruch digest and applied-search material.
- `conventional-ml-essentials` (Vol IV, NEW) — see section 4. Seeded by the existing spec + the user's pending document.
- `ml-interview-program` (spine, NEW, thin) — contains: (1) `essentials.sty`, the shared preamble extracted from the two identical main.tex preambles (colors, tcolorboxes, badges, \stronganswer/\redflags/\followups macros, math macros) — each volume's main.tex shrinks to \usepackage{essentials} + its includes; sync via a `make sync-style` script or git subtree, since the volumes must stay independently cloneable; (2) `part0_kernel.tex` — the 26-principle kernel, authored ONCE here; (3) the master question index, cross-volume study plans, and the numbers card; (4) drill builds (runnable Python for coding rounds); (5) a CI script that runs per-volume `latexmk`, checks for duplicate \label collisions ACROSS volumes (namespace labels `dl:`, `nlp:`, `sr:`, `cml:` — this also fixes the NLP ch1/ch2 label collision class of bug permanently), and greps a `facts.yaml` drift-sentinel file (canonical facts like 'GPT-2 = pre-norm', 'Chinchilla ≈ 20 tok/param', the GPT-2 perplexity number) against all four volumes so the contradictions the reviewers found (section 2) cannot silently reappear.

**Part 0 kernel, program-wide:** the 26 principles are authored in the spine repo and \input into EACH volume's front matter as a compact Part 0 (8-12 pages), with per-volume 'kernel hooks' — each chapter opens by naming which principles it instantiates. This upgrades the previously approved DL-only P3 Part 0 into the program's shared mental model. The Core-50 tier likewise becomes a program-wide tier: ~50 must-know items drawn from all four volumes, listed in the master index with volume/chapter pointers, and each item's chapter section carries a Core-50 margin badge.

**Cross-volume referencing convention:** PDFs can't hyperlink each other, so standardize textual refs: [DL 5.3], [NLP 9.2], [SR 4], [CML 3]. Add a one-page 'Program Map' to every volume's front matter showing all four volumes, the tracks (section 5), and where each overlap zone's canonical home lives — this is the contract that makes 'pointer + role-specific angle' edits (section 2) legible to the reader.

**Candidate experience ('what do I read tonight'):** the spine repo's study-plan layer is the single entry point. It ships: (a) a 2-week breadth sprint, (b) 4-week depth tracks per specialization (LLM track, Search/RecSys track, Multimodal track), (c) a 1-week coding-round drill schedule, (d) a night-before Core-50 + numbers-card pass. Every plan line item is a [Vol chapter/section] pointer, so the candidate opens exactly one PDF per session. Build tooling: top-level Makefile in the spine repo with `make all | dl | nlp | sr | cml | index` (per-volume latexmk), so 'rebuild everything' is one command.
