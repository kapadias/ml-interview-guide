\begin{tldr}
This chapter covers vision architectures beyond basic CNNs: Vision Transformers (ViT), hierarchical transformers (Swin), object detection (YOLO, DETR), and segmentation (U-Net, Mask R-CNN, SAM). Understanding the trade-offs between CNNs and Transformers, and when to use each detection/segmentation approach, is crucial for vision-related interview questions.

\section{CNN Fundamentals Review}
\label{sec:cnn_review}

\subsection{Inductive Biases of CNNs}

\begin{enumerate}
    \item \textbf{Locality}: Neurons connect only to local regions
    \item \textbf{Translation equivariance}: Same filter applied everywhere
    \item \textbf{Weight sharing}: Same parameters across spatial locations
\end{enumerate}

These biases make CNNs data-efficient for vision but limit modeling of global context.

\subsection{Receptive Field}

\textbf{Receptive Field.} The region in the input that affects a particular activation.

For a stack of $L$ layers with kernel size $k$ and stride 1:
\begin{equation}
RF = 1 + L \times (k - 1)
\end{equation}

With dilated convolutions (dilation $d$):
\begin{equation}
\text{effective kernel} = k + (k-1)(d-1)
\end{equation}

\subsection{Patch Embedding}

Split image into non-overlapping patches and linearly project:
\begin{equation}
\vz_0 = [\vx_{cls}; \vx_p^1\mE; \vx_p^2\mE; \ldots; \vx_p^N\mE] + \mE_{pos}
\end{equation}

where:
\begin{itemize}
    \item $\vx_p^i \in \R^{P^2 \cdot C}$ is flattened patch
    \item $\mE \in \R^{(P^2 \cdot C) \times D}$ is patch embedding projection
    \item $P$ = patch size (typically 16)
    \item $N = \frac{H \cdot W}{P^2}$ = number of patches
\end{itemize}

\subsection{Feature Pyramid from Swin}

Like CNNs, Swin produces multi-scale features:
\begin{itemize}
    \item Stage 1: $\frac{H}{4} \times \frac{W}{4}$, 96 channels
    \item Stage 2: $\frac{H}{8} \times \frac{W}{8}$, 192 channels
    \item Stage 3: $\frac{H}{16} \times \frac{W}{16}$, 384 channels
    \item Stage 4: $\frac{H}{32} \times \frac{W}{32}$, 768 channels
\end{itemize}

This makes Swin directly usable for detection and segmentation.

\subsection{Two-Stage Detectors (Faster R-CNN)}

\begin{enumerate}
    \item \textbf{Backbone}: Extract features (ResNet, etc.)
    \item \textbf{RPN (Region Proposal Network)}: Propose candidate boxes
    \item \textbf{RoI Pooling/Align}: Extract features for each proposal
    \item \textbf{Classification + Regression}: Classify and refine boxes
\end{enumerate}

\textbf{Pros}: High accuracy, well-understood
\textbf{Cons}: Slower, complex pipeline

\subsection{One-Stage Detectors}

\subsubsection{YOLO (You Only Look Once)}

\begin{itemize}
    \item Divide image into grid
    \item Each cell predicts $B$ boxes + confidences + class probs
    \item Single forward pass
\end{itemize}

\textbf{Evolution}: YOLOv1 → v2 → v3 → v4 → v5 → v8 (continuous improvements)

\subsubsection{SSD (Single Shot Detector)}

\begin{itemize}
    \item Multi-scale feature maps
    \item Predictions at multiple scales
    \item Default boxes (anchors) at each location
\end{itemize}

\subsubsection{RetinaNet}

\textbf{Key innovation}: Focal loss to handle class imbalance
\begin{equation}
FL(p_t) = -\alpha_t (1-p_t)^\gamma \log(p_t)
\end{equation}

\subsection{DETR (Detection Transformer)}

\textbf{Key innovations}:
\begin{enumerate}
    \item \textbf{Set prediction}: Output fixed set of predictions, no NMS needed
    \item \textbf{Bipartite matching}: Hungarian algorithm to match predictions to GT
    \item \textbf{Object queries}: Learned queries attend to image features
\end{enumerate}

\begin{equation}
\mathcal{L} = \sum_{i=1}^{N} [\lambda_{cls} \mathcal{L}_{cls}(c_i, \hat{c}_{\sigma(i)}) + \lambda_{box} \mathcal{L}_{box}(b_i, \hat{b}_{\sigma(i)})]
\end{equation}

where $\sigma$ is the optimal assignment from Hungarian matching.

\section{Instance Segmentation}
\label{sec:instance_segmentation}
%==============================================================================

\subsection{Task Definition}

Detect individual objects AND segment each instance separately.

\subsection{Mask R-CNN}

Extension of Faster R-CNN:
\begin{enumerate}
    \item Everything in Faster R-CNN
    \item + Mask head: Predict binary mask for each RoI
    \item RoI Align (not RoI Pool) for better spatial alignment
\end{enumerate}

\begin{equation}
\mathcal{L} = \mathcal{L}_{cls} + \mathcal{L}_{box} + \mathcal{L}_{mask}
\end{equation}

\subsection{SAM (Segment Anything Model)}

\textbf{Foundation model for segmentation}:
\begin{itemize}
    \item Trained on 11M images, 1B masks
    \item Promptable: Point, box, or text prompts
    \item Zero-shot transfer to new domains
\end{itemize}

\begin{interviewq}
\textbf{Q: CNN vs ViT for a dataset with only 10K labeled images---how do you decide, and what changes with 10M images?}

\badgeLfive{L5} \quad \badgetype{Trade-off} \quad \badgefreq{\freqhigh}

\stronganswer The core tradeoff is inductive bias vs.\ data-driven learning. CNNs have strong built-in biases (locality, translation equivariance, weight sharing) that make them data-efficient. ViTs have minimal inductive bias and rely on learning spatial structure from data, requiring much more data to match CNNs.

\textit{With 10K labeled images:} CNN is the clear winner from scratch. A ResNet-50 trained on 10K images will significantly outperform a ViT-B trained from scratch because the ViT must learn what convolutions provide for free---local feature extraction, spatial hierarchy. However, a pre-trained ViT (from CLIP, DINOv2, or ImageNet-21K) fine-tuned on 10K images will likely beat a randomly initialized CNN. So the real question is: \textbf{do you have a good pre-trained model?} If yes, ViT wins due to superior pre-trained features. If training from scratch, CNN wins.

\textit{With 10M images:} ViT catches up and surpasses CNN. At this scale, ViT's flexibility becomes an advantage---it learns task-specific spatial patterns that may be more optimal than CNN's hardcoded biases. ViT also scales better with model size: doubling a ViT's parameters gives consistent gains, while CNN scaling has diminishing returns. The crossover point where ViT matches CNN (without pre-training) is roughly 1M images, though this depends on task complexity.

\textit{Practical recommendation:} Almost always use a pre-trained model. CLIP ViT-B/16 fine-tuned on 10K domain-specific images is a strong default. If latency is critical (mobile/edge), use EfficientNet or MobileNet. If you need multi-scale features (detection, segmentation), use Swin Transformer or ConvNeXt.

\redflags
\begin{itemize}
    \item ``ViT is always better because it's newer''---data efficiency matters
    \item Ignoring the option of pre-trained models (the most practical choice)
    \item Not knowing that ViTs struggle with small datasets when trained from scratch
\end{itemize}

    \item \badgeLseven{L7} Discusses ConvNeXt (CNN with ViT design principles that matches ViT at scale), DINOv2 as a universal pre-trained backbone, and the inductive bias hypothesis vs.\ data scale hypothesis

\begin{interviewq}
\textbf{Q: Estimate the FLOPs for a ResNet-50 forward pass on a $224 \times 224$ image. How does this compare to ViT-B/16?}

\badgeLsix{L6} \quad \badgetype{Estimation} \quad \badgefreq{\freqmed}

\stronganswer I'll estimate FLOPs by computing the dominant operations: convolutions for ResNet and matrix multiplications for ViT.

\textit{ResNet-50 FLOPs.} A convolution layer with kernel $k \times k$, input channels $C_{in}$, output channels $C_{out}$, and spatial output $H \times W$ requires $2 \times k^2 \times C_{in} \times C_{out} \times H \times W$ FLOPs. ResNet-50 has 4 stages of bottleneck blocks. The largest contribution comes from the middle stages.

Rough breakdown: Stage 1 ($56 \times 56$, 256 channels): $\sim$0.3 GFLOPs. Stage 2 ($28 \times 28$, 512 channels): $\sim$0.8 GFLOPs. Stage 3 ($14 \times 14$, 1024 channels): $\sim$1.5 GFLOPs. Stage 4 ($7 \times 7$, 2048 channels): $\sim$1.0 GFLOPs. Initial conv + FC: $\sim$0.2 GFLOPs. Total: $\approx$ \textbf{4.1 GFLOPs}. (Actual: 4.1 GFLOPs, so this estimate is accurate.)

\textit{ViT-B/16 FLOPs.} With patch size 16, a $224 \times 224$ image produces $N = 196$ patches (+1 CLS = 197 tokens). Hidden dim $D = 768$, 12 layers, 12 heads.

Per-layer self-attention: $4 \times N \times D^2$ (QKV projection + output) $+ 2 \times N^2 \times D$ (attention scores + weighted sum) $= 4 \times 197 \times 768^2 + 2 \times 197^2 \times 768 \approx 465\text{M} + 60\text{M} = 525\text{M}$.

Per-layer FFN: $2 \times N \times D \times 4D = 2 \times 197 \times 768 \times 3072 \approx 930\text{M}$.

Per layer total: $\sim$1.45 GFLOPs. $\times$ 12 layers: $\approx$ \textbf{17.6 GFLOPs}. (Actual: $\sim$17.6 GFLOPs.)

\textit{Comparison:} ViT-B/16 is $\sim$4.3$\times$ more FLOPs than ResNet-50, but has more parameters (86M vs 25M) and generally higher accuracy. The FLOPs gap closes with efficient ViT variants (DeiT with distillation, EfficientViT) and widens with higher resolutions (ViT attention is $O(n^2)$ in patches).

\redflags
\begin{itemize}
    \item Not knowing the general magnitude (GFLOPs, not MFLOPs or TFLOPs)
    \item Forgetting that ViT attention is $O(n^2)$ in sequence length, making resolution increases expensive
    \item Treating FLOPs as a direct proxy for wall-clock time (ignores memory bandwidth, parallelism)
\end{itemize}

\begin{interviewq}
\textbf{Q: Design a vision backbone for real-time object detection on an edge device (e.g., mobile phone or drone with $<$10W power budget).}

\badgeLsix{L6} \quad \badgetype{Architecture Design} \quad \badgefreq{\freqmed}

\stronganswer Edge deployment imposes hard constraints: latency $<$30ms per frame (for 30+ FPS), model size $<$20MB (limited storage), peak memory $<$500MB, and power $<$10W. These eliminate standard ResNets and ViTs---I need an efficient backbone + detector co-design.

\textit{Backbone options.} (1) \textbf{MobileNetV3-Small} ($\sim$2.5M params, $\sim$56 MFLOPs): Uses inverted residual blocks with depthwise separable convolutions, squeeze-and-excitation, and hardware-aware NAS. (2) \textbf{EfficientNet-B0} ($\sim$5.3M params, $\sim$390 MFLOPs): Compound scaling, slightly heavier but higher accuracy. (3) \textbf{EfficientViT-M} series: Lightweight ViT designed for mobile, competitive with MobileNet on accuracy-latency frontier.

\textit{Detection head.} YOLO-based head (YOLOv8-nano): single-stage, anchor-free, with depthwise separable convolutions in the neck. The complete YOLOv8-nano model is $\sim$3.2M parameters, $<$10 GFLOPs, achieving 37\% mAP on COCO at 30+ FPS on mobile.

\textit{Optimization stack:} (1) Quantization: INT8 quantization reduces model size 4$\times$ and speeds up inference 2--3$\times$ on mobile NPUs. Use quantization-aware training (QAT) to minimize accuracy loss. (2) Pruning: Remove 30--50\% of filters with structured pruning, then fine-tune. (3) Export: Convert to TensorRT (NVIDIA), CoreML (Apple), or TFLite (Android) for hardware-specific optimizations. (4) Knowledge distillation: Train the small model to mimic a larger teacher (e.g., YOLOv8-large) on the same dataset.

\textit{Resolution tradeoff.} Edge models often use $320 \times 320$ or $416 \times 416$ input (vs.\ $640 \times 640$ for server models). This $4\times$ reduction in pixels translates to $\sim$4$\times$ fewer FLOPs in the backbone and $\sim$4$\times$ fewer detection locations. The accuracy loss is manageable for close-range detection.

\textit{Profiling.} Always profile on the target hardware, not just count FLOPs. Memory access patterns, operator support, and NPU utilization vary dramatically across devices. A model with fewer FLOPs can be slower if it uses operators that aren't accelerated.

\redflags
\begin{itemize}
    \item Proposing a full ResNet-50 or ViT-B---these don't meet edge constraints
    \item Optimizing only for FLOPs without considering memory and hardware-specific bottlenecks
    \item Forgetting quantization---it's essential for edge deployment
\end{itemize}

\begin{interviewq}
\textbf{Q: What is the effective receptive field of a CNN and why does it matter for architecture design?}

\badgeLfive{L5} \quad \badgetype{Conceptual} \quad \badgefreq{\freqmed}

\stronganswer The \textit{theoretical} receptive field of a neuron is the region in the input that can possibly affect its activation. For $L$ layers of $k \times k$ convolutions with stride 1: $RF = 1 + L(k-1)$. So a 3-layer network with $3 \times 3$ kernels has $RF = 7 \times 7$. With dilated convolutions (dilation $d$), the effective kernel size grows to $k + (k-1)(d-1)$, enabling much larger receptive fields without more parameters.

However, the \textit{effective} receptive field is much smaller than the theoretical one. Luo et al.\ (2016) showed that CNN neurons have a Gaussian-shaped sensitivity profile: they're most sensitive to the center of the receptive field and nearly insensitive to the periphery. The effective RF grows proportionally to $O(\sqrt{n})$ where $n$ is depth, much slower than the theoretical $O(n)$.

\textit{Why it matters for architecture design:}

(1) \textbf{Object scale vs.\ receptive field.} To classify or detect an object, the network must ``see'' the entire object. If the effective RF at a given layer is smaller than the object, the model relies on stitching together partial information in later layers. This is why deep networks (ResNet-50+) are needed for large objects and why multi-scale feature pyramids (FPN) are essential for detection.

(2) \textbf{Dilated convolutions for segmentation.} DeepLab uses atrous convolutions to exponentially increase the receptive field without losing spatial resolution. This is critical for semantic segmentation where both large RF and dense predictions are needed.

(3) \textbf{Why ViTs sidestep this.} ViTs have global receptive field from layer 1 (self-attention attends to all patches). This fundamentally changes the dynamics: a single ViT layer can relate distant image regions, while a CNN needs many layers to achieve the same. This partly explains ViTs' advantage on tasks requiring global understanding.

(4) \textbf{Pooling and strided convolutions.} These effectively increase the receptive field by reducing spatial resolution. The tradeoff: larger RF but lost fine-grained spatial detail.

\redflags
\begin{itemize}
    \item Confusing theoretical and effective receptive field
    \item Not knowing that effective RF is much smaller than theoretical
    \item Ignoring the connection between receptive field and multi-scale detection
\end{itemize}

\begin{interviewq}
\textbf{Q: Your ViT model achieves 92\% accuracy on ImageNet but only 65\% on your domain-specific dataset despite fine-tuning. Diagnose the problem.}

\badgeLsix{L6} \quad \badgetype{Debugging} \quad \badgefreq{\freqmed}

\stronganswer A large accuracy gap between ImageNet and a domain-specific dataset after fine-tuning suggests a distribution shift or fine-tuning configuration problem. I would investigate systematically.

\textit{Hypothesis 1: Domain gap.} ImageNet contains natural images. If your domain is satellite imagery, medical scans, or microscopy, the visual statistics are fundamentally different. Check: what does the domain data look like? If it's a different modality (grayscale, multi-channel, very different resolution), the pre-trained features may not transfer well. Solution: use a domain-specific pre-trained model (e.g., SSL pre-training on unlabeled domain data), or use a model pre-trained on a broader dataset (CLIP, DINOv2).

\textit{Hypothesis 2: Resolution mismatch.} ViTs are sensitive to input resolution because position embeddings are learned for a specific grid size. If your domain images are much higher or lower resolution than $224 \times 224$, position embedding interpolation introduces errors. Check: what resolution are the domain images? Solution: bicubic interpolation of position embeddings, but better to fine-tune at the target resolution with a warmup period. For very different resolutions, consider retraining position embeddings from scratch.

\textit{Hypothesis 3: Fine-tuning hyperparameters.} Common mistakes: (a) learning rate too high---catastrophic forgetting of pre-trained features (loss spikes early). (b) Learning rate too low---model barely moves from pre-trained weights (not adapting to domain). (c) No layer-wise LR decay---lower layers should have smaller LR to preserve general features. (d) Too few epochs. Check: plot training and validation loss curves. Solution: grid search over LR $\in [1\text{e-}5, 5\text{e-}4]$, use cosine schedule with warmup, layer-wise LR decay factor 0.65--0.75.

\textit{Hypothesis 4: Class distribution mismatch.} ImageNet has 1000 balanced classes. If your domain has 5 classes with severe imbalance (95\% one class), the fine-tuning head needs class-weighted loss or oversampling.

\textit{Hypothesis 5: Data quality.} Small or noisy labeled dataset. If you have $<$1K images per class, overfitting is likely. Check: is validation accuracy much lower than training? Solution: stronger augmentation (RandAugment, Mixup, CutMix), regularization (higher dropout, weight decay), or collect more data.

\textit{Systematic approach:} Start with the simplest diagnostic---plot train/val curves. If overfitting: more augmentation and regularization. If underfitting: increase LR or model capacity. If both are low: the features don't transfer (domain gap).

\redflags
\begin{itemize}
    \item ``Just train longer''---without checking for overfitting vs.\ underfitting
    \item Ignoring resolution mismatch for ViT
    \item Not considering domain gap as the primary hypothesis
\end{itemize}

\begin{interviewq}
\textbf{Q: Design a visual search system that handles 100M product images with sub-200ms latency. Walk through the architecture.}

\badgeLsix{L6} \quad \badgetype{Architecture Design} \quad \badgefreq{\freqmed}

\stronganswer I'd design a two-stage system: offline embedding + online retrieval with reranking.

\textit{Offline pipeline.} (1) Extract embeddings using CLIP ViT-B/16 (512-dim) for all 100M images. CLIP over ImageNet-pretrained models because CLIP captures semantic similarity (``red dress'') not just visual similarity (color histograms). Processing: batch inference on A100 GPUs at $\sim$1000 images/s, so 100M images $\approx$ 28 GPU-hours. (2) Build an HNSW index (Faiss) over the 512-dim embeddings. Memory: $100\text{M} \times 512 \times 4$ bytes $\approx$ 200 GB for FP32, or 100 GB with FP16. For tighter memory, use IVF-PQ (product quantization): compress to 64 bytes per vector $\to$ 6.4 GB, with some recall loss. (3) Store product metadata (title, price, category) in a separate database, linked by image ID.

\textit{Online serving.} Query image arrives $\to$ (1) encode with CLIP ViT-B/16 ($\sim$15--20 ms on GPU), (2) ANN search in HNSW for top-100 candidates ($\sim$2--5 ms), (3) optional reranking stage using a cross-encoder that jointly processes query-candidate pairs for top-100 ($\sim$50--100 ms), (4) return top-20 with metadata. Total: $\sim$100--150 ms, well within 200ms budget.

\textit{Cross-modal support.} CLIP's aligned embedding space enables text-to-image search for free: encode text query with CLIP text encoder, search the same image index. No changes to the index.

\textit{Index updates.} HNSW supports incremental insertion for new products. Periodic full rebuild (weekly) to maintain optimal graph structure. Use a versioned index with blue-green deployment for zero-downtime updates.

\textit{Scaling.} Shard the index across multiple machines for larger catalogs or higher QPS. Each shard handles a partition of the embedding space. Aggregate and merge-sort top-k results from each shard.

\begin{interviewq}
\textbf{Q: Explain how DETR works and why it represents a paradigm shift in object detection.}

\badgeLfive{L5} \quad \badgetype{Conceptual} \quad \badgefreq{\freqhigh}

\stronganswer DETR (Detection Transformer, Carion et al., ECCV 2020) reimagines object detection as a direct \textit{set prediction} problem, eliminating all hand-crafted components from the detection pipeline.

\textit{Architecture.} (1) A CNN backbone (ResNet-50) extracts a feature map from the input image. (2) A Transformer encoder processes the flattened feature map with self-attention, allowing global reasoning across the entire image. (3) A Transformer decoder receives $N$ learnable ``object queries'' (typically $N = 100$) and produces $N$ predictions via cross-attention to the encoder output. Each query specializes in detecting certain object types, sizes, or spatial regions. (4) Each prediction is a tuple (class, bounding box), with class ``no object'' for empty slots.

\textit{Training: bipartite matching.} The key innovation is using the Hungarian algorithm to find the optimal one-to-one assignment between predictions and ground truth objects. The matching cost combines classification loss and box regression loss (L1 + GIoU). This eliminates the need for anchor boxes and NMS entirely---the set loss naturally prevents duplicate detections.

\textit{Why it's a paradigm shift.} (1) \textbf{End-to-end}: No anchor design, no NMS, no hand-tuned IoU thresholds. The entire detection pipeline is differentiable. (2) \textbf{Global reasoning}: Self-attention enables reasoning about object relationships (e.g., ``this region is already claimed by another query''). (3) \textbf{Simplicity}: The code is dramatically simpler than Faster R-CNN. (4) \textbf{Extensibility}: Trivially extends to panoptic segmentation by adding a mask head.

\textit{Limitations.} (1) Slow training: 500 epochs (vs.\ 12--36 for Faster R-CNN) because attention is initially diffuse. (2) Weak on small objects: global attention dilutes focus on small regions. (3) Fixed number of queries limits max detections per image.

\textit{Improvements.} Deformable DETR uses deformable attention (attend to learned sparse points instead of all positions), reducing training to 50 epochs and improving small-object detection. DINO-DETR adds denoising training and contrastive queries, achieving SOTA.

\redflags
\begin{itemize}
    \item Not mentioning bipartite matching---it's DETR's most important innovation
    \item Saying ``DETR is always better than Faster R-CNN''---it has real limitations
    \item Confusing object queries with image patch tokens
\end{itemize}

\begin{interviewq}
\textbf{Q: Compare the ResNet skip connection to DenseNet dense connections to Swin Transformer's shifted windows. What problem does each solve?}

\badgeLsix{L6} \quad \badgetype{Trade-off} \quad \badgefreq{\freqmed}

\stronganswer Each connection pattern addresses a fundamental challenge in deep vision architectures.

\textit{ResNet skip connections (2015).} Problem: vanishing gradients in very deep networks (100+ layers). Solution: add the input directly to the output ($y = F(x) + x$). The network learns a residual $F(x)$ rather than the full transformation. Gradient flows directly through the skip path, enabling stable training of 152+ layer networks. The identity shortcut also provides an ``information highway''---layers can pass features unchanged when the identity mapping is optimal.

\textit{DenseNet dense connections (2017).} Problem: feature reuse is limited in ResNet (each block only accesses its own input). Solution: connect every layer to every subsequent layer within a block. Layer $l$ receives feature maps from all preceding layers: $x_l = H_l([x_0, x_1, \ldots, x_{l-1}])$ via concatenation. Benefits: (1) maximum feature reuse, (2) implicit deep supervision (every layer has a short path to the loss), (3) fewer parameters per layer (each layer only adds $k$ new channels, called ``growth rate''). Downside: memory-intensive due to concatenation, requiring careful memory management.

\textit{Swin shifted windows (2021).} Problem: ViT's global self-attention is $O(n^2)$ in sequence length, making it prohibitively expensive for high-resolution images. Solution: compute self-attention within local windows ($7 \times 7$), then shift the window partition in alternating layers. Regular windows provide efficient local attention; shifted windows enable cross-window communication without global attention. Complexity becomes $O(n)$ instead of $O(n^2)$. The hierarchical structure (progressive downsampling) produces multi-scale feature maps like CNNs, making Swin directly compatible with FPN for detection and segmentation.

\textit{Common thread.} All three solve information flow problems. ResNet solves gradient flow (depth). DenseNet solves feature reuse (breadth). Swin solves long-range dependency vs.\ efficiency (spatial scale). Modern architectures often combine these insights: ConvNeXt uses residual connections with depthwise convolutions, while Swin uses both windowed attention and hierarchical pooling.

\redflags
\begin{itemize}
    \item Not knowing that DenseNet uses concatenation (not addition like ResNet)
    \item Saying Swin uses global attention---it uses local windowed attention
    \item Missing the computational complexity distinction ($O(n^2)$ vs.\ $O(n)$)
\end{itemize}
