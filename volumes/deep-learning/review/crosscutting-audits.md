# coverageGaps

SUMMARY: The book is strong on transformer internals, distributed training basics (Ch 15), inference/serving (Ch 22), RLHF through PPO/DPO/PRMs (Ch 20), RAG design (Ch 24), and safety/guardrails (Ch 23). However, it has whole-topic gaps in exactly the areas 2026 frontier-lab Staff loops have shifted toward: (1) agents and tool use are entirely absent; (2) there is no pretraining-at-scale chapter (web-scale data curation/dedup/mixing, tokenizer training at corpus scale, run operations, fault tolerance and checkpointing at 10k-GPU scale); (3) the post-training chapter stops at the 2023 stack — GRPO, RLVR, and reasoning-model/test-time-compute training recipes are missing; (4) the entire 24,712-line book contains exactly one code listing, so it provides zero preparation for hands-on ML coding rounds (implement attention/backprop/BPE from scratch), which are a hard gate at these labs; (5) LLM-specific evaluation practice (benchmark suites, contamination, eval infrastructure, launch A/Bs) is thin; (6) GPU hardware/kernel fundamentals are scattered rather than treated; (7) LLM product design ('design ChatGPT') and (8) behavioral/staff-level rounds (project deep-dive, research discussion) have no coverage at all. Verified by reading README.md and main.tex and grepping all files under /home/user/deep-learning-essentials/sections/.

## [critical] Agents and tool use: completely absent
Grep across sections/ finds no coverage of function calling, tool schemas, agent loops (ReAct/plan-execute), MCP-style integration, context management for agents, sandboxing/computer use, multi-agent orchestration, or agentic evaluation (SWE-bench, tau-bench, pass^k reliability). The only hits are incidental 'agentic RAG loop' mentions in sections/24_long_context_rag.tex (lines 402, 770-800). In 2026 loops at OpenAI/Anthropic-tier labs this is now a first-class interview area: system-design rounds routinely ask 'design a coding agent' or 'why do agents fail on long-horizon tasks', and domain rounds probe tool-call formatting, error recovery, trajectory evaluation, and how tool use is trained (SFT on trajectories, RL on task success). A Staff candidate with no vocabulary here will fail an entire round.

**Recommendation:** Add a new chapter 'Agents and Tool Use' (Part V, after Ch 24). Proposed outline: (1) Function calling mechanics — tool schemas, constrained decoding, parallel tool calls, how tool use is trained into models; (2) Agent loop architectures — ReAct, plan-and-execute, orchestrator/sub-agent patterns, when multi-agent helps vs hurts; (3) Context engineering — memory, compaction, retrieval vs long context for agents, MCP-style tool integration; (4) Reliability engineering — error recovery, guardrails on actions, sandboxing, human-in-the-loop gates; (5) Agentic evals — SWE-bench/tau-bench/OSWorld, pass@k vs pass^k, trajectory-level vs outcome-level evaluation, cost/latency budgets; (6) Training agents — SFT on trajectories, RL with verifiable task rewards; (7) 8-10 interview questions including 'design a coding assistant agent', 'your agent succeeds 90% per step but fails 50% per task — diagnose', and 'how would you evaluate an agent before launch'.

## [critical] GRPO, RLVR, and reasoning models / test-time compute: the post-training chapter stops at the 2023 stack

# structureFindings

SUMMARY: The book is a strong deep-dive reference (248 tagged questions, consistent interviewq scaffolds with red flags/follow-ups, good tcolorbox infrastructure) but it is structurally a textbook, not layered preparation material. It has exactly two layers — a one-paragraph tldr per chapter and 25,000 lines of prose — with no night-before layer in between: no formula sheet, no per-chapter one-pager, and Quick Reference sections exist in only 2 of 24 chapters. The part organization is actively broken: files 17-19 are included after 20-24 with no counter overrides, so compiled chapter numbers contradict both the filenames and every table in README.md. Must-know material is unmarked at any actionable granularity (118 of 248 questions are 'high frequency' — a tier that filters nothing), questions have no labels or numbers so plans can only reference whole chapters, answers sit directly under questions making self-testing impossible, and the hand-maintained 1047-line appendix index has already drifted (248 vs 249 counts, duplicate rows). The highest-leverage fixes, all local to this codebase: (1) a standardized end-of-chapter Quick Reference + a generated cheat-sheet appendix, (2) auto-numbered, labeled interviewq boxes with a Core-50 tier styled via the existing tcolorbox key mechanism, (3) an etoolbox answers-toggle enabling a questions-only drill build from the same source, and (4) file renumbering plus a 2026 frontier-lab part regrouping that promotes the LLM/serving/alignment chapters out of the back of the book.

## [critical] Missing fast-path layer: no night-before review is possible

## [high] Chapter numbering is broken: compiled PDF contradicts filenames and README

**Recommendation:** git mv the section files so filename order equals include order (20_reinforcement_learning.tex → 17_..., 21→18, 22→19, 23→20, 24→21, 17_production→22, 18_evaluation→23, 19_decision→24), update the nine \include lines in main.tex, and regenerate the README tables from the new order.
